Beyond running as a long-lived webhook server, a probot-go app can execute directly inside a GitHub Actions workflow. In this mode there is no HTTP server, no signature verification, and no persistent process — the app reads the event payload that GitHub pre-loads into the runner, dispatches it through your registered handlers, then exits. This is ideal for lightweight automations that only need to react to a single event type per run.

## How RunAction Works

```go
func (p *Probot) RunAction() error
```

When called, `RunAction`:

1. Reads `GITHUB_EVENT_PATH` — the filesystem path to the event JSON file GitHub writes before invoking the action.
2. Reads `GITHUB_EVENT_NAME` — the name of the triggering event (e.g. `issues`, `push`).
3. Parses the JSON payload from the file at `GITHUB_EVENT_PATH`.
4. Uses `GITHUB_RUN_ID` as the delivery ID (falls back to `"action"` if unset).
5. Calls `Receive()` with the constructed `WebhookEvent`, dispatching handlers exactly as the HTTP server would.
6. Returns immediately after all handlers finish — no blocking, no server loop.

`RunAction` returns an error if either `GITHUB_EVENT_PATH` or `GITHUB_EVENT_NAME` is not set, or if the event file cannot be read or parsed.

<Note>
  Webhook signature verification is **skipped** in action mode — GitHub writes the payload directly to disk on the runner, so there is no inbound HTTP request to sign.
</Note>

## Authentication in Action Mode

Inside a GitHub Actions workflow the `GITHUB_TOKEN` secret is automatically injected into every job. Use it as `GithubToken` instead of an App ID and private key:

```go
opts, _ := probot.OptionsFromEnv() // reads GITHUB_TOKEN from environment
app, _ := probot.New(opts)
```

`OptionsFromEnv()` maps the `GITHUB_TOKEN` environment variable directly to `Options.GithubToken`, so no extra configuration is needed.

<Warning>
  `GITHUB_TOKEN` permissions are scoped to the repository that triggered the workflow. If your handler needs to access other repositories, register a proper GitHub App and supply `APP_ID` and `PRIVATE_KEY` as repository secrets instead.
</Warning>

## Detection Pattern

The recommended approach is to detect the `GITHUB_ACTIONS` environment variable and branch between action mode and server mode. This lets the same binary work in both contexts:

```go
if os.Getenv("GITHUB_ACTIONS") == "true" {
    if err := app.RunAction(); err != nil {
        log.Fatal().Err(err).Msg("action failed")
    }
    return
}

// Fallback: run as a long-lived webhook server.
probot.NewServer(probot.ServerOptions{Probot: app}).Start()
```

This pattern comes directly from the `example/basic` application in the source repository.

## Workflow File

<Steps>
  <Step title="Create the workflow file">
    Add `.github/workflows/bot.yml` to your repository:

    ```yaml
    name: probot-go bot

    on:
      issues:
        types: [opened]
      pull_request:
        types: [opened, synchronize]

    jobs:
      run-bot:
        runs-on: ubuntu-latest
        permissions:
          issues: write
          pull-requests: write
          contents: read
        steps:
          - uses: actions/checkout@v4

          - uses: actions/setup-go@v5
            with:
              go-version: "1.22"

          - name: Run bot
            env:
              GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
            run: go run ./cmd/bot
    ```
  </Step>

  <Step title="Write the bot entrypoint">
    The bot reads the event from the environment and dispatches it through your handlers:

    ```go
    package main

    import (
        "os"

        "github.com/rs/zerolog/log"
        probot "github.com/Pratyay360/probot-go"
    )

    func main() {
        opts, err := probot.OptionsFromEnv()
        if err != nil {
            log.Fatal().Err(err).Msg("invalid options")
        }

        app, err := probot.New(opts)
        if err != nil {
            log.Fatal().Err(err).Msg("failed to create probot")
        }

        app.On("issues.opened", func(ctx *probot.Context) error {
            ctx.Log().Info().Msg("issue opened via action")
            return nil
        })

        if os.Getenv("GITHUB_ACTIONS") == "true" {
            if err := app.RunAction(); err != nil {
                log.Fatal().Err(err).Msg("action failed")
            }
            return
        }

        probot.NewServer(probot.ServerOptions{Probot: app}).Start()
    }
    ```
  </Step>

  <Step title="Verify the action runs">
    Open a new issue in the repository. The workflow triggers, the `issues.opened` handler fires, and the run exits with code 0. Check the **Actions** tab for the structured log output.
  </Step>
</Steps>

## Environment Variables Reference

<Accordion title="Variables set automatically by GitHub Actions">
  | Variable | Description |
  |---|---|
  | `GITHUB_ACTIONS` | Set to `"true"` in all Actions runners. Use this to detect action mode. |
  | `GITHUB_EVENT_PATH` | Path to the JSON file containing the full event payload. |
  | `GITHUB_EVENT_NAME` | Name of the triggering event, e.g. `issues` or `pull_request`. |
  | `GITHUB_RUN_ID` | Unique ID for the workflow run. Used as the delivery ID by `RunAction`. |
  | `GITHUB_TOKEN` | Short-lived installation token scoped to the current repository. |
</Accordion>

<Accordion title="Variables you supply as secrets">
  | Variable | Description |
  |---|---|
  | `APP_ID` | Numeric GitHub App ID. Required if using App auth instead of `GITHUB_TOKEN`. |
  | `PRIVATE_KEY` | PEM private key for the GitHub App. Required if using App auth. |
  | `WEBHOOK_SECRET` | Only needed when running as a server; not used by `RunAction`. |
</Accordion>
